# Blimp 引擎 Lua 脚本指南

本文介绍怎样用 Lua 编写 Blimp 的游戏逻辑：脚本放在哪里、什么时候运行、能调用哪些引擎接口（实体、输入、移动与碰撞、声音、灯光组、相机），最后逐段讲解城堡关卡的脚本 `assets/scripts/castle.luacn`。

本文假设你已经会写 Lua，不讲 Lua 语言本身。引擎内嵌的是 **LuaJIT**（Lua 5.1 语法），矢量和四元数是 FFI 结构体。

![城堡关卡的编辑器界面](images/lua/editor.jpg)

---

## 1. 核心规则：Lua 发命令、查状态，不保存状态

这是整个脚本系统的前提，后面每个接口都按它设计：

- **游戏状态归引擎所有**。实体的位置、速度、声音都存在 Odin 那一侧；Lua 每帧读取它们，算出结果，再写回去。
- **脚本里不留会变的东西**。不要在脚本的全局或 upvalue 里存计时器、状态机、"上一帧的值"。顶层的 `令` / `本地` 只放常量（速度、半径、方向向量）。
- 需要随时间变化的东西，有两种写法：
  1. **写成时间的函数**：`世界.时间()` 是运行世界的游戏时钟，暂停时停止。城门、旗帜、探照灯都按 `世界.时间()` 算出当前姿态，不需要任何记忆。
  2. **存进实体字段**：例如玩家的竖直速度存在 `玩家` 实体的 `velocity` 字段里。字段不够用就在实体 schema 里加一个（见 [4.4](#44-自定义字段)）。
  3. **存进 `游戏` 表**：要带到下一个关卡的东西（血量、钥匙、从哪个入口出现）。关卡一换，它的实体就没了，`游戏` 表跟着运行走（见 [14](#14-切换关卡)）。

这样做的好处是：**脚本随时可以从头重新执行**。保存脚本时引擎热重载它，游戏不会因此坏掉。

## 2. 脚本文件与运行方式

### 2.1 两种脚本

| | 世界脚本 | 引擎脚本 |
|---|---|---|
| 文件 | 关卡的世界设置里的 `script` 路径，如 `assets/scripts/castle.lua` | 固定为 `assets/scripts/main.lua` |
| 何时运行 | 只在关卡**运行（Play）**时 | 引擎启动后整个会话 |
| 回调 | `世界.开始()`、`世界.更新(时间差)` | `引擎.开始()`、`引擎.更新(时间差)`、`引擎.完结()` |
| `世界.*` / `实体.*` 作用于 | 这个运行中的关卡 | 没有世界：调用会在日志里报错，什么也不做 |

**游戏逻辑写在世界脚本里。** 引擎脚本没有世界可以操作，只适合整个会话的逻辑（比如读 `输入.*`）。

两种脚本的加载方式完全一样：每个脚本运行在自己的环境表里（找不到的名字回落到全局 `_G`），所以同时打开的两个关卡的脚本互不覆盖全局变量。脚本里的 `世界`（引擎脚本里是 `引擎`）也是它自己的表，回调只属于这个脚本。下面“变量要先声明”的规则和 2.5 的 `引入` 对两种脚本都适用。

**每个变量都要先声明。** 给没用 `令`（或 `本地`）声明过的名字赋值是错误：脚本停下，日志和错误浮层里写明哪一行、哪个名字。忘了声明的变量本来会悄悄留到下一帧，变成脚本里的状态，所以干脆不允许。读全局（`打印`、`数学`、`世界`）和给表的字段赋值（`函数 世界.更新(...)`）不受影响。

```lua
令 速度 = 2          -- 正确
函数 世界.更新(时间差)
    令 t = 世界.时间()  -- 正确
    距离 = t * 速度      -- 错误：assignment to undeclared variable '距离'
结束
```

### 2.2 LuaCN：中文关键字的 Lua

脚本可以写成 `.luacn`：关键字是中文，构建时（以及编辑器热重载时）转译成同名的 `.lua`。**关卡引用的是 `.lua`，但要改的是 `.luacn`**，生成的 `.lua` 会被覆盖。也可以直接写普通 `.lua`，所有接口都有英文名。

| LuaCN | Lua | LuaCN | Lua |
|---|---|---|---|
| `令` / `本地` | `local` | `返回` | `return` |
| `函数` | `function` | `结束` | `end` |
| `如果` / `那么` | `if` / `then` | `否则如果` / `否则` | `elseif` / `else` |
| `当` / `做` | `while` / `do` | `对于` / `在` | `for` / `in` |
| `重复` / `直到` | `repeat` / `until` | `中断` | `break` |
| `真` / `假` / `空` | `true` / `false` / `nil` | `和` / `或` / `非` | `and` / `or` / `not` |

常用标准库也有中文别名：`打印`(print)、`转文本`(tostring)、`转数字`(tonumber)、`遍历`(pairs)、`遍历列表`(ipairs)、`安全调用`(pcall)、`字符串.格式化`(string.format)、`表.插入`(table.insert) 等，完整列表在 `assets_engine/scripts/lua_chinese_defs.lua`。

### 2.3 给关卡挂脚本

1. 打开关卡，点视口工具栏上的齿轮按钮打开**世界设置**，在 `script` 里填脚本路径（项目相对路径，如 `assets/scripts/castle.lua`）。
2. 齿轮旁边的 `<>` 按钮用 VS Code 打开这个脚本；如果它是由 `.luacn` 生成的，打开的是 `.luacn`。
3. 按 **F5** 运行。

运行相关的功能键：

| 键 | 作用 |
|---|---|
| F5 | 运行：复制一份关卡来运行，脚本执行 `世界.开始()` |
| F6 | 暂停 / 继续。暂停时 `世界.更新` 不调用，`世界.时间()` 不走 |
| F10 | 暂停时单步一帧 |
| F7 | 停止。运行副本被丢弃，编辑中的关卡**从不**被运行修改 |
| F8 | 运行的视口在游戏模式（通过相机实体看，输入交给游戏）和编辑器相机之间切换，游戏继续运行。鼠标被锁定时用它（或 Alt+Tab）拿回光标 |

运行时只有按 F5 的那个视口变成游戏画面，其他窗口（别的视口、面板、游戏全局变量）照常显示。同一时间只能运行一个关卡：另一个关卡在运行时按 F5 不会开始，左下角提示先停止（F7）。

运行的是关卡的**副本**：脚本把吊桥转了、把玩家移走了，停止后关卡还是原样，也不会被保存。

### 2.4 热重载与报错

- 保存任何脚本（关卡脚本、引擎脚本，或它们引入的模块，放在 `assets/` 下任何位置），所有脚本都会从头重新加载：引擎脚本马上重新执行 `引擎.开始()`，每个正在运行的关卡**重新执行 `世界.开始()`**。因为脚本不保存状态，这总是安全的。
- 脚本出错时，错误写进日志，这个关卡的脚本停止运行，直到你保存修改（热重载）或停止后重新运行。不会每帧刷屏。
- `打印(...)` 输出到引擎日志（控制台）。
- `.luacn` 在保存时（热重载）、引擎启动时和每次按下运行时都会转译成 `.lua`，所以运行的总是你最后写的版本。

### 2.5 拆成多个文件：引入

关卡脚本和引擎脚本都可以把代码拆到别的文件里，用 `引入`（英文 `require`）按**项目相对路径**加载。文件放在 `assets/` 下任何位置都行，`.lua` 可以省略：

```lua
-- 关卡脚本（世界设置的 script）
令 玩家模块 = 引入("assets/characters/player")
令 敌人模块 = 引入("assets/characters/enemy")
令 炮塔模块 = 引入("assets/props/turret")

函数 世界.更新(时间差)
    令 玩家位置 = 玩家模块.更新(时间差)
    敌人模块.更新(时间差, 玩家位置)
    炮塔模块.更新(时间差, 玩家位置)
结束
```

模块就是一个函数表，最后 `返回` 它：

```lua
-- assets/characters/enemy.luacn
令 敌人 = {}
令 速度 = 1.5          -- 顶层只放常量

函数 敌人.更新(时间差, 玩家位置)
    -- 读写实体
结束

返回 敌人
```

- **数据怎么共享**：不用全局变量。实体上的东西（玩家位置、血量）各个模块直接从实体读；关卡脚本算出来的值当参数传下去；大家都要看、又不属于某个实体的状态（比如警报等级），加成实体字段（见 [4.4](#44-自定义字段)）。
- 同一个模块可以被多个关卡引入。每个运行中的关卡各自加载一份，互不共享；每次运行、每次热重载都重新加载。
- 模块和关卡脚本用同一个环境：`世界`、`实体` 指的是这个关卡，“变量要先声明”的规则同样适用。
- 路径写错、互相引入（A 引入 B，B 又引入 A）都会报错，并指出是哪个文件哪一行。

## 3. 生命周期回调

```lua
function 世界.开始()
    -- 运行开始时执行一次（脚本热重载后也会再执行一次）
end

function 世界.更新(时间差)
    -- 关卡每走一帧调用一次；时间差 是这一帧的秒数
    令 t = 世界.时间()   -- 自运行开始的游戏秒数，暂停时停止
end
```

英文写法是 `function World.start()` / `function World.update(dt)` / `World.time()`。

还有两个可选回调：

- `函数 世界.动画事件(实体号, 名字)`（`World.anim_event`）：角色的动画片段播过标好的时刻（比如脚落地）时调用，见第 13 节。
- `函数 世界.界面()`（`World.ui`）：每帧都调用，暂停时也调用，画游戏的屏幕界面，见第 15 节。

- `世界.更新` 只在关卡真正前进的帧调用：暂停时不调用，F10 单步时调用一次。
- 动画请基于 `世界.时间()`，不要在 Lua 里自己累加时间。

## 4. 实体

### 4.1 句柄

实体就是句柄。Lua 拿到的是一个整数，所有实体接口都以它为第一个参数。

| 中文 | 英文 | 说明 |
|---|---|---|
| `世界.查找(名称)` | `World.find(name)` | 按名称找实体，返回 `句柄, 是否找到` |
| `世界.获取(名称)` | `World.get(name)` | 按名称取一个必须存在的实体，返回句柄；找不到时在日志和错误浮层里警告（每个名称每次加载脚本只警告一次） |
| `实体.有效(句柄)` | `Entity.valid(h)` | 句柄是否还指向一个存在的实体 |
| `世界.添加(名称, 模型, 位置)` | `World.add(name, model, pos)` | 新建实体，返回句柄。`模型` 是资产键，如 `"assets/models/castle.gltf:flag001"`；名称重复时自动改成 `name_1` 这样的唯一名 |
| `世界.移除(句柄)` | `World.remove(h)` | 删除实体 |

名称可以是中文（城堡关卡的实体全是中文名），按 UTF-8 存储，最长 64 字节，约 21 个汉字。

`世界.查找` 很便宜，每帧按名称查找就是推荐写法。找不到时句柄无效，`实体.有效` 返回假，后续对它的读写都是安全的空操作：

```lua
令 灯 = 世界.查找("探照灯")
如果 非 实体.有效(灯) 那么 返回 结束
```

两者的区别在于找不到时算不算错误。实体应该一直在（城门、玩家、主相机），找不到说明它在编辑器里被改名或删掉了，用 `世界.获取`，这样按下运行就能看到警告，不会默默失效。找不到本身就是答案（导弹的目标已经死了，改为直飞），用 `世界.查找`，它不报任何东西：

```lua
令 目标, 还在 = 世界.查找(目标名)
如果 还在 那么 -- 追踪目标
否则 -- 直飞
结束
```

关卡里固定的部件（城门、吊桥、探照灯）也可以在 `世界.开始` 里用 `世界.获取` 取一次，存进脚本顶层的本地变量，在 `世界.更新` 里直接用。这样是安全的：实体被删掉后，存着的句柄会变无效（句柄带代数，槽位重用后旧句柄也不会指向新实体）；每次按下运行、每次脚本热重载都会重新执行 `世界.开始`，重新取句柄。

```lua
令 闸门

函数 世界.开始()
    闸门 = 世界.获取("闸门")
结束

函数 世界.更新(时间差)
    如果 非 实体.有效(闸门) 那么 返回 结束
    -- 移动闸门
结束
```

但凡会在运行中生成、死亡或重生的实体（敌人、导弹的目标、`世界.添加` 新建的东西），都要每帧用 `世界.查找`：存着的句柄在实体删掉后永远无效，同名的新实体（比如重生出来的）它找不到，开始时还不存在的实体它也找不到。

> 运行中用 `世界.添加` 生成的实体目前不参与碰撞（物理世界在运行开始时建好）。

### 4.2 读写字段

实体是一个"胖结构体"，所有字段都按名称读写。接口按值的类型区分：

| 类型 | 读 | 写 | 适用字段 |
|---|---|---|---|
| 数字 | `实体.取数(e, 字段)` | `实体.设数(e, 字段, 值)` | `f32`、整数、枚举（序号）、标志位（位掩码） |
| 布尔 | `实体.取布尔(e, 字段)` | `实体.设布尔(e, 字段, 值)` | `bool` |
| 文本 | `实体.取文本(e, 字段)` | `实体.设文本(e, 字段, 值)` | 名称、模型、声音等字符串 |
| 矢量 | `实体.取矢量(e, 字段)` | `实体.设矢量(e, 字段, 矢量3)` | `vec3` |
| 四元数 | `实体.取四元数(e, 字段)` | `实体.设四元数(e, 字段, 四元数)` | `quat` |

英文名：`Entity.get_number / set_number / get_bool / set_bool / get_string / set_string / get_vec3 / set_vec3 / get_quat / set_quat`。

字段名用 schema 里的**英文 id**（编辑器检查器里显示的是中文标签）。字段名写错或类型不对时，读返回零值，写不生效。

```lua
令 门 = 世界.查找("闸门")
令 位置 = 实体.取矢量(门, "position")
实体.设矢量(门, "position", 矢量3(位置.x, 0.6, 位置.z))
实体.设数(世界.查找("主塔火把"), "intensity", 2.0)
```

位置、朝向、缩放和“隐藏”是每个实体都有的字段，有专门的接口，不用写字段名：

| 读 | 写 | 英文 | 说明 |
|---|---|---|---|
| `实体.取位置(e)` | `实体.设位置(e, 矢量3)` | `Entity.get_position / set_position` | 世界坐标的 `position` |
| `实体.取朝向(e)` | `实体.设朝向(e, 四元数)` | `Entity.get_rotation / set_rotation` | `rotation` |
| `实体.取缩放(e)` | `实体.设缩放(e, 矢量3)` | `Entity.get_scale / set_scale` | `scale` |
|  | `实体.平移(e, 位移)` | `Entity.translate(e, delta)` | 位置加上 `位移`（世界坐标） |
|  | `实体.旋转(e, 四元数)` | `Entity.rotate(e, q)` | 在本地坐标里转：`朝向 = 朝向 * q` |
| `实体.是否隐藏(e)` | `实体.隐藏(e) / 实体.取消隐藏(e)` | `Entity.is_hidden / hide / unhide` | 基本标志里的“隐藏”：隐藏后不画，碰撞和声音不受影响 |

```lua
令 门 = 世界.查找("闸门")
实体.平移(门, 矢量3(0, 时间差 * 0.3, 0))     -- 每秒上升 0.3
实体.旋转(世界.查找("风车"), 四元数.轴角(前, 时间差))
如果 玩家死了 那么 实体.隐藏(世界.查找("玩家")) 结束
```

按名称读写（上面那组接口）留给 schema 里的其他字段，比如 `intensity`、`velocity`。

### 4.3 常用字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | 文本 | 名称，在一个关卡里唯一 |
| `position` / `rotation` / `scale` | 矢量 / 四元数 / 矢量 | 变换 |
| `model` | 文本 | 模型资产键 |
| `basic_flags` | 标志 | 位 0 = 启用（Enabled），位 1 = 隐藏（Hidden） |
| `basic_static_flags` | 标志 | 位 0 = 静态（Static），位 1 = 可渲染（Renderable），位 2 = 投射间接光（Cast Indirect） |
| `camera_type` | 枚举 | 0 无，1 透视，2 正交 |
| `light_type` | 枚举 | 0 无，1 平行光，2 点光源，3 聚光灯，4 圆柱光 |
| `color` / `intensity` | 矢量 / 数字 | 灯光颜色与强度；在有模型的实体上是模型的颜色乘数（白色 × 1 = 原样） |
| `fov` / `inner_fov` | 数字 | 相机视角；聚光灯外 / 内锥角（度） |
| `range` | 矢量（x, y） | 灯光：照射范围；声音：x 以内满音量，到 y 线性衰减为零 |
| `light_group` | 数字 | 灯光所属的光源组，0 = 不可切换（见第 8 节） |
| `sound` / `volume` / `sound_flags` | 文本 / 数字 / 标志 | 实体自带的声音（见第 7 节） |
| `collision` | 枚举 | 0 无，1 包围盒，2 碰撞网格（`_col`），3 渲染网格 |
| `velocity` | 矢量 | 游戏自用的速度，不保存到关卡文件 |

标志位按位掩码读写，例如隐藏一个实体：

```lua
令 标志 = 实体.取数(e, "basic_flags")       -- 1 = 只启用
实体.设数(e, "basic_flags", 标志 + 2)          -- 加上 Hidden（假设原来没有隐藏）
```

**会被脚本移动的实体不要勾"静态"**。静态实体参与探针烘焙，也是物理里的静态刚体；城堡里的吊桥、闸门、旗帜都只设了 Renderable。

### 4.4 自定义字段

字段定义在项目根目录的 `entity_schema.ini`（也可以用引擎内的 schema 编辑器修改），构建时生成 `src/gen_entity.odin`。新加的字段**不需要重新生成任何绑定**，Lua 立即可以按名称读写。城堡玩家用的 `velocity` 就是这样一个游戏字段。

## 5. 数学库

| 中文 | 英文 | |
|---|---|---|
| `矢量2/3/4(x, y, …)` | `Vec2/3/4` | 支持 `+ - *`（与数字或同类相乘）、取负；方法 `:点乘 :叉乘 :长度 :标准化 :插值` |
| `四元数(x, y, z, w)` | `Quat` | `四元数.单位()`、`四元数.轴角(轴, 弧度)`、`四元数.欧拉角(俯仰, 偏航, 滚转)`；方法 `:旋转(矢量) :球面插值 :逆 :共轭 :标准化` |
| `矩阵3` / `矩阵4` | `Mat3` / `Mat4` | `矩阵4.变换矩阵(位置, 旋转, 缩放)`、`:变换点 :变换方向 :逆矩阵` 等 |
| `数学.*` | `CMath.*` | `圆周率 正弦 余弦 反正切2 反正弦 开方 夹紧 截断(0–1) 插值 平滑阶跃 向下取整 角度转弧度 …` |

- 四元数相乘 `a * b` 表示先做 `b` 再做 `a`（相对本地坐标）。城堡里 `四元数.轴角(上, 偏航) * 四元数.轴角(右, 俯仰)` 是先抬头低头、再左右转。
- `四元数:旋转(矢量)` 把向量转到这个朝向下，例如 `朝向:旋转(矢量3(0, 0, 1))` 是朝前的方向。
- 角度一律是**弧度**。

**坐标系**：左手系，**Y 向上，+Z 向前**，+X 向右。

## 6. 输入

输入只在**游戏视口有焦点**时有效：按 F5 运行的那个视口就是游戏视口，点一下它，按键和鼠标就交给游戏；点别的面板，游戏就收不到输入（所有按键读作松开、所有轴读作 0），在编辑器里打字不会传进游戏。游戏视口有焦点时编辑器只响应功能键（F3、F6、F7、F8、F10、F11），字母、Esc、Delete 都归游戏。

| 中文 | 英文 | 说明 |
|---|---|---|
| `输入.按住(键)` | `Input.down(key)` | 现在是否按着 |
| `输入.按下(键)` | `Input.pressed(key)` | 这一帧刚按下 |
| `输入.松开(键)` | `Input.released(key)` | 这一帧刚松开 |
| `输入.鼠标按住(n)` / `输入.鼠标按下(n)` | `Input.mouse_down / mouse_pressed` | 鼠标键 1–5：1 左键，2 中键，3 右键 |
| `输入.鼠标移动()` | `Input.mouse_delta()` | 这一帧鼠标移动的像素（矢量2，+y 向下），锁定鼠标时也有效 |
| `输入.锁定鼠标(布尔)` | `Input.lock_mouse(b)` | 隐藏光标并锁在窗口内（鼠标视角）。回到编辑器时自动放开，回到游戏时重新锁定 |

## 7. 声音

声音文件（`.wav .ogg .mp3 .flac`）在启动时全部解码，用项目路径作为键，例如 `"assets/sounds/jump.wav"`。Lua 拿不到声音句柄：**要控制的声音就挂在实体上，实体就是句柄。**

### 7.1 实体上的声音

在编辑器里给实体设置：

- `sound`：声音文件；`volume`：音量；
- `sound_flags`：**开始时播放**（运行开始自动播放）、**循环**、**空间定位**；
- `range`：x 以内满音量，到 y 线性衰减为零。

| 中文 | 英文 | 说明 |
|---|---|---|
| `实体.播放声音(e)` | `Entity.play_sound(e)` | 按这个实体的 sound / volume / range / sound_flags 播放，声音跟着实体移动。没播出来返回假 |
| `实体.停止声音(e)` | `Entity.stop_sound(e)` | 停止它的声音 |

### 7.2 一次性声音

| 中文 | 英文 | 说明 |
|---|---|---|
| `世界.播放声音(键 [, 音量])` | `World.play_sound(key [, volume])` | 不在空间中的声音：音乐、界面音效，哪里听都一样大 |
| `世界.在位置播放声音(键, 位置 [, 音量])` | `World.play_sound_at(key, pos [, volume])` | 在某一点播放，按默认范围随距离衰减 |

注意：

- 同时最多 32 个声音。满了以后挤掉听起来最小的；新声音比所有正在播放的都小时直接丢弃。
- 同一个声音文件 0.05 秒内只会响一次（循环声音除外），每帧调用播放不会叠成噪音，但也不会每帧都响。
- 听者是正在显示运行世界的那个视口的相机（游戏模式下就是游戏相机）。
- 暂停时声音暂停，停止运行时全部停止。编辑中的关卡不发声。

## 8. 灯光组

灯光组用来在运行时整体调节一批灯：停电、蜡烛闪烁、窗户的灯一开一关。

- 每个关卡最多 **4 个**可切换的组，在**世界设置 → 光源组**里命名，并设置初始强度 `scale` 和闪烁图案 `pattern`。
- 每盏灯的 `light_group` 字段指定它属于哪个组（1–4）。0 组永远满强度。
- 组的强度同时作用于这些灯的**实时直接光**和**烘焙的间接光**（每个组烘焙在探针的独立一层），所以关灯后墙上的反光也一起消失。
- `pattern` 是 Quake 风格的灯光图案：每个字母持续 0.1 秒，循环；`a` = 0，`m` = 1，`z` ≈ 2；留空表示常亮。城堡的火把组用的是 `mmnmmommommnonmmonqnmmo`。

| 中文 | 英文 | 说明 |
|---|---|---|
| `世界.设光源组(名称, 强度)` | `World.set_light_group(name, scale)` | 0 = 关，1 = 和保存/烘焙时一样。没有这个名称的组时返回假 |
| `世界.光源组(名称)` | `World.light_group(name)` | 当前强度（不含闪烁图案） |

名称不区分大小写。最终亮度 = 组强度 × 闪烁图案当前的值，所以对火把组调用 `世界.设光源组("torches", 0.5)` 后它仍然闪烁，只是整体暗了一半。脚本设置的强度只属于这次运行，不会保存。

| 所有组 = 1 | 所有组 = 0 |
|---|---|
| ![灯光组全开](images/lua/lights_on.jpg) | ![灯光组全关](images/lua/lights_off.jpg) |

上图是城堡关卡把 `torches`、`beacon`、`windows` 三组全开和全关的对比：城门两侧的火把、右侧角楼的信标和庭院里的篝火都熄灭了，只剩平行光 `sun` 和探照灯（都在 0 组）。

## 9. 移动与碰撞

物理目前只提供**查询**：不做模拟，没有刚体下落。"东西怎么掉"由 Lua 自己决定（重力写进位移里）。

### 9.1 哪些实体会挡路

运行开始时，引擎给每个启用、且 `collision` 不为"无"的实体建一个碰撞体：

| `collision` | 形状 | 适合 |
|---|---|---|
| 无 | 不碰撞 | 旗子、装饰小物 |
| 包围盒 | 模型包围盒 × 缩放 | 树、石头，最便宜 |
| 碰撞网格（默认） | 套件里的 `<模型>_col` 网格 | 美术专门做了简化碰撞的模型 |
| 渲染网格 | 模型的所有三角形 | 低多边形的城墙、地面 |

勾了"静态"的实体是静态碰撞体；其他的会**跟着实体移动**——脚本转动吊桥，玩家就会被吊桥挡住。

### 9.2 角色移动

```lua
令 着地 = 实体.角色移动(e, 位移, 半径, 高度)   -- Entity.move_character(e, delta, radius, height)
```

给玩家、NPC 这类在场景里走动的角色用。引擎用物理（Box3D）把实体当成一个站在它 `position` 上的胶囊体（半径、总高度），移动 `位移`，沿碰撞面滑动：撞墙停下，斜坡和台阶会走上去。结果直接写进实体的 `position`。返回值表示结束时是否站在地面上（法线 y ≥ 0.7 的面算地面）。实体自己的碰撞体会被忽略。

只想直接改位置、不需要碰撞（吊桥、闸门、旗帜）就直接设 `position` / `rotation` 字段。

位移已经乘过 `时间差`；重力也是位移的一部分。速度要跨帧保留就存进实体字段（见第 10 节玩家的写法）。

### 9.3 射线检测

```lua
令 命中, 点, 法线, 实体号 = 世界.射线检测(起点, 方向, 距离)   -- World.raycast(origin, dir, dist)
```

沿射线找第一个碰撞（方向不必是单位向量），返回是否命中、命中点、表面法线和命中的实体句柄。

## 10. 相机

游戏画面通过运行世界里**第一个启用的相机实体**（`camera_type` 不为"无"）来渲染。控制相机就是写它的 `position` 和 `rotation`，和任何实体一样。

城堡的 `主相机` 在关卡里摆成编辑器的俯瞰视角；脚本在 `世界.开始()` 里把它转到玩家的朝向，之后每帧放到玩家眼睛的位置。

## 11. 调试

- `打印(...)` 输出到引擎日志。调试版引擎会把最近几秒的错误和警告显示在窗口左下角，脚本出错时不用去翻控制台；`blimpctl log` 列出最近的日志。
- `世界.调试线(起点, 终点 [, 颜色])` / `World.debug_line(from, to [, color])` 在这个世界的所有视口里（包括游戏模式）画一条线，只保留到下一帧，所以要在 `世界.更新` 里每帧画。暂停时线会保留。适合看射线、路径、触发范围：

  ```lua
  local 起点 = 实体.取矢量(玩家, "position")
  世界.调试线(起点, 起点 + Vec3(0, 0, 8), Vec4(1, 0.3, 0.3, 1))
  ```

- 调试版引擎可以用 `bin/blimpctl.exe` 从命令行执行 Lua：

  ```
  blimpctl worlds                      # 列出世界，运行副本的序号在这里
  echo print(World.time()) | blimpctl lua 1 -
  ```

  `lua <世界> -` 让 `World.*` / `Entity.*` 作用于指定的世界，适合在运行中的关卡里测试射线、声音、灯光组。例如在城堡的运行副本里从玩家眼睛向前打一条射线：

  ```
  local p = World.find("玩家")
  local hit, pt, n, e = World.raycast(Entity.get_vec3(p, "position") + Vec3(0, 0.34, 0), Vec3(0, 0, 1), 8)
  print(hit, Entity.get_string(e, "name"), pt)
  -- true    小树_1    Vec3(-2.98023e-08, 0.335, 1.60769)
  ```

- 暂停（F6）后可以用 `blimpctl lua` 改实体、改灯光组，画面立即反映，而脚本不会把它覆盖回去，因为暂停时 `世界.更新` 不运行。

## 12. 示例：城堡关卡

`assets/scenes/castle.level` 的世界设置里 `script = assets/scripts/castle.lua`，它由 `assets/scripts/castle.luacn` 生成。脚本做了六件事：城门开关、城门音效、探照灯扫动、旗帜飘动、灯光组变化，以及一个第一人称玩家。所有动画都只是 `世界.时间()` 的函数；唯一跨帧的状态（玩家的竖直速度）存在实体字段里。玩家的代码在模块 `assets/characters/player.luacn` 里，办公室关卡也引入它（见 12.6 和 14）；跟着玩家的狐狸在模块 `assets/characters/fox.luacn` 里（见 12.8）。

### 12.1 常量与工具函数

```lua
令 上 = 矢量3(0, 1, 0)
令 右 = 矢量3(1, 0, 0)
令 前 = 矢量3(0, 0, 1)

-- 固定部件的句柄，世界.开始 里用 世界.获取 取（找不到会警告）。
令 吊桥, 闸门, 探照灯, 城门声, 玩家, 相机

令 函数 平滑(x)
    x = 数学.截断(x)
    返回 x * x * (3 - 2 * x)
结束
```

顶层只有常量、纯函数和固定部件的句柄。句柄在 `世界.开始` 里取（见 12.7），各个系统直接用，不再每帧查找（见 4.1）。`平滑` 是 0–1 的 smoothstep 缓动。

### 12.2 城门：用时间算出姿态

```lua
-- 城门循环，0 = 关闭并升起，1 = 打开并放下：开 6 秒，关闭 2 秒，关 5 秒，打开 2 秒。
令 函数 城门开度(t)
    令 p = t % 15
    如果 p < 6  那么 返回 1 结束
    如果 p < 8  那么 返回 1 - 平滑((p - 6) / 2) 结束
    如果 p < 13 那么 返回 0 结束
    返回 平滑((p - 13) / 2)
结束

令 函数 更新城门(t)
    令 开度 = 城门开度(t)
    令 朝向 = 四元数.轴角(上, 数学.圆周率 / 2)   -- 城门朝 -Z（它的套件部件偏航了 90 度）

    -- 吊桥：铰链在原点，沿本地 +X 平放；升起时绕本地 Z 把 +X 往上转。
    如果 实体.有效(吊桥) 那么
        实体.设朝向(吊桥, 朝向 * 四元数.轴角(前, (1 - 开度) * 数学.角度转弧度(80)))
    结束

    -- 闸门：城门打开时从拱门里升起（在吊桥放下之前先升）。
    如果 实体.有效(闸门) 那么
        令 位置 = 实体.取位置(闸门)
        实体.设位置(闸门, 矢量3(位置.x, 平滑(开度 * 1.5) * 0.6, 位置.z))
    结束
结束
```

要点：

- `城门开度(t)` 是一个 15 秒循环的纯函数。任意时刻（包括热重载之后、单步之后）都能直接算出城门该在哪，不需要"当前状态"变量。
- 吊桥的旋转 = 基础朝向 × 绕本地 Z 的抬起角度。四元数右乘表示在本地坐标里旋转。
- 闸门只改 `position.y`，x、z 从实体上读出来原样写回。
- 吊桥和闸门的 `collision` 不为"无"、也不是静态，所以物理碰撞体跟着它们动：吊桥升起时玩家走不过去。

| 打开（t % 15 < 6） | 关闭（8 ≤ t % 15 < 13） |
|---|---|
| ![城门打开](images/lua/gate_open.jpg) | ![城门关闭](images/lua/gate_closed.jpg) |

### 12.3 城门音效：检测"越过"某个时刻

```lua
-- 越过 = 这一帧越过了 间隔 的整数倍。
令 函数 越过(t, 时间差, 间隔)
    返回 数学.向下取整(t / 间隔) ~= 数学.向下取整((t - 时间差) / 间隔)
结束

令 函数 更新城门声音(t, 时间差)
    如果 越过(t - 6, 时间差, 15) 或 越过(t - 13, 时间差, 15) 那么   -- 开始关闭 / 开始打开
        实体.播放声音(城门声)
    结束
结束
```

不保存"上次播放的时间"，而是比较这一帧的开始和结束是否跨过了 6 秒、13 秒这两个节点。`城门声` 是放在城门处的一个空实体，它的 `sound = assets/sounds/gate.wav`、`sound_flags = 空间定位`、`range = 0.5, 10`，脚本只管"现在播"，怎么播由实体字段决定。

### 12.4 探照灯与旗帜

```lua
令 函数 更新探照灯(t)
    如果 非 实体.有效(探照灯) 那么 返回 结束
    令 偏航 = 数学.圆周率 + 数学.正弦(t * 0.5) * 数学.角度转弧度(70)
    实体.设朝向(探照灯, 四元数.轴角(上, 偏航) * 四元数.轴角(右, 数学.角度转弧度(38)))
结束

令 函数 更新旗帜(t)
    令 i = 1
    当 真 做
        令 旗 = 世界.查找("旗帜_" .. i)
        如果 非 实体.有效(旗) 那么 中断 结束
        令 摆动 = 数学.正弦(t * 2.3 + i * 1.7) * 0.35 + 数学.正弦(t * 5.1 + i) * 0.08
        实体.设朝向(旗, 四元数.轴角(上, 摆动))
        i = i + 1
    结束
结束
```

- 探照灯是一个投射阴影的聚光灯实体，转它的 `rotation` 就是转光束：先向下俯 38°，再左右扫 ±70°。
- 旗帜按命名约定 `旗帜_1`、`旗帜_2`……每帧用 `世界.查找` 逐个查找，直到找不到为止：这里找不到不是错误，而是数完了，所以不用 `世界.获取`。在编辑器里多复制一面旗（复制会自动编号）脚本就会让它一起飘，不用改代码。每面旗的相位 `i * 1.7` 不同，所以不会整齐划一。

### 12.5 灯光组

```lua
-- 光源组（世界设置）：信标闪烁，大厅的窗户每 20 秒里暗 4 秒。
令 函数 更新灯光(t)
    世界.设光源组("beacon", 0.55 + 0.45 * 数学.正弦(t * 3))
    世界.设光源组("windows", (t % 20) < 16 和 1 或 0)
结束
```

城堡的世界设置里有三个组：`torches`（火把，带闪烁图案）、`beacon`（城门塔上的信标）、`windows`（大厅窗户）。火把的闪烁完全由图案完成，脚本不用管；信标用正弦做呼吸效果；窗户每 20 秒熄灭 4 秒。因为组强度也作用于烘焙的间接光，窗户熄灭时它照在庭院里的反光也会消失。

### 12.6 第一人称玩家

`玩家` 是一个没有模型的实体，代表站在它 `position` 上的胶囊；`主相机` 每帧跟到它的眼睛处。

玩家的代码不在 castle.luacn 里，而在模块 `assets/characters/player.luacn`：办公室关卡也有玩家，两个关卡引入同一个模块（见 [2.5](#25-拆成多个文件引入)）。模块不保存状态，句柄由关卡脚本在 `世界.开始` 里取好传进去：

```lua
令 玩家模块 = 引入("assets/characters/player")
令 出生点   = 矢量3(0, 0.05, -6)

函数 世界.更新(时间差)
    玩家模块.更新(玩家, 相机, 世界.时间(), 时间差, 出生点)
结束
```

两个关卡的比例不一样：城堡是小人国，办公室是真人大小。所以模块里的半径、身高、速度、跳跃、重力都是"玩家缩放为 1 时"的数，每帧乘上 `玩家` 实体的 `scale.x`（下面代码里的 `大小`）。城堡的玩家 scale 是 1，办公室的是 4，手感一样。

![游戏模式下的第一人称视角](images/lua/game_fps.jpg)

**视角：从相机现在的朝向反推偏航和俯仰。** 脚本不存"当前偏航角"，而是每帧从相机的 `rotation` 算出来，加上这一帧的鼠标 / 右摇杆输入：

```lua
令 朝前 = 实体.取朝向(相机):旋转(前)
令 鼠标 = 输入.鼠标移动()
令 偏航 = 数学.反正切2(朝前.x, 朝前.z) + 鼠标.x * 灵敏度 + 输入.手柄轴("rightx") * 摇杆看速 * 时间差
令 俯仰 = -数学.反正弦(数学.夹紧(朝前.y, -1, 1)) + 鼠标.y * 灵敏度 + 输入.手柄轴("righty") * 摇杆看速 * 时间差
俯仰 = 数学.夹紧(俯仰, -1.4, 1.4)
令 朝向 = 四元数.轴角(上, 偏航) * 四元数.轴角(右, 俯仰)
```

**移动：键盘和左摇杆合成一个方向。**

```lua
令 向前 = 矢量3(数学.正弦(偏航), 0, 数学.余弦(偏航))
令 向右 = 矢量3(数学.余弦(偏航), 0, -数学.正弦(偏航))
令 前后 = -输入.手柄轴("lefty")
令 左右 = 输入.手柄轴("leftx")
如果 输入.按住("W") 那么 前后 = 前后 + 1 结束
如果 输入.按住("S") 那么 前后 = 前后 - 1 结束
如果 输入.按住("D") 那么 左右 = 左右 + 1 结束
如果 输入.按住("A") 那么 左右 = 左右 - 1 结束
-- （长度超过 1 时归一化，按住左 Shift / 按下左摇杆时用跑速）
令 水平 = (向前 * 前后 + 向右 * 左右) * (速度 * 大小)
```

**重力、跳跃与碰撞：竖直速度存在实体字段里。**

```lua
令 竖直 = 实体.取矢量(玩家, "velocity").y - 重力 * 大小 * 时间差
令 着地 = 实体.角色移动(玩家, 矢量3(水平.x * 时间差, 竖直 * 时间差, 水平.z * 时间差), 半径 * 大小, 身高 * 大小)
如果 着地 和 竖直 < 0 那么 竖直 = -0.1 * 大小 结束   -- 轻轻压住地面，下一帧还算着地
如果 着地 和 (输入.按下("Space") 或 输入.手柄按下("a")) 那么
    竖直 = 跳速 * 大小
    世界.播放声音("assets/sounds/jump.wav", 0.5)
结束
实体.设矢量(玩家, "velocity", 矢量3(0, 竖直, 0))
```

这里是"Lua 不保存状态"的标准写法：读字段 → 计算 → `实体.角色移动` → 写回字段。速度在 `玩家` 实体上，脚本热重载后玩家照样在空中继续下落。

**相机跟随、出界复位、脚步声：**

```lua
令 位置 = 实体.取位置(玩家)
如果 位置.y < 出生点.y - 5 * 大小 那么   -- 掉出了世界：回到出生点（关卡脚本传进来的）
    位置 = 出生点
    实体.设位置(玩家, 位置)
    实体.设矢量(玩家, "velocity", 矢量3(0, 0, 0))
结束
令 眼 = 位置 + 上 * (眼高 * 大小)
实体.设位置(相机, 眼)
实体.设朝向(相机, 朝向)

-- 在地上走动时每 步距时间 一步，跑时按速度加快。
如果 着地 和 长 > 0.1 和 越过(t, 时间差, 步距时间 * 走速 / 速度) 那么
    世界.在位置播放声音("assets/sounds/footstep.wav", 位置, 0.7)
结束
```

脚步声用的 `越过` 和 12.3 节的一样（模块里有自己的一份）：每跨过一个步距就响一声，不需要计步器。

**射线检测：按 E / 手柄 X 沿视线打一条 8 个身位（8 × 大小）的射线。**

```lua
如果 输入.按下("E") 或 输入.手柄按下("x") 那么
    令 命中, 点, 法线, 实体号 = 世界.射线检测(眼, 朝向:旋转(前), 8 * 大小)
    如果 命中 那么
        世界.在位置播放声音("assets/sounds/ping.wav", 点)
        打印("射线命中 " .. 实体.取文本(实体号, "name") .. " " .. 转文本(点))
    结束
结束
```

### 12.7 回调

```lua
函数 世界.开始()

    闸门   = 世界.获取("闸门")
```

### 12.8 狐狸：会跟着玩家的角色

`狐狸` 是一个带骨骼动画的模型（`assets/characters/Fox.gltf`），它跟着玩家：离得远就跑，近了就走，到了身边停下张望。和玩家一样，它的代码是一个模块（`assets/characters/fox.luacn`），关卡脚本只取句柄、每次更新调用它，并把动画事件转给它：

```lua
令 狐狸模块 = 引入("assets/characters/fox")

函数 世界.动画事件(实体号, 名字)
    狐狸模块.动画事件(狐狸, 实体号, 名字)
结束

函数 世界.更新(时间差)
    ...
    狐狸模块.更新(狐狸, 玩家, 时间差)   -- 第二个参数是它跟着的目标
结束
```

模块里的整段逻辑是第 13 节的典型写法：

```lua
函数 狐狸模块.更新(狐狸, 目标, 时间差)
    ...
    -- 跑起来后要近一点才慢下来，停下张望后要远一点才再走，免得在边界上来回切换。
    令 跑的距离 = 动画.播放中(狐狸, "Run") 和 2.5 或 3
    令 走的距离 = 动画.播放中(狐狸, "Survey") 和 1.2 或 0.8

    令 速度, 姿态 = 0, 空
    如果 距离 > 跑的距离 那么
        速度 = 跑速
        姿态 = 动画.采样(狐狸, "Run", 播放倍率(狐狸, "Run", 速度))
    否则如果 距离 > 走的距离 那么
        速度 = 走速
        姿态 = 动画.采样(狐狸, "Walk", 播放倍率(狐狸, "Walk", 速度))
    否则
        姿态 = 动画.采样(狐狸, "Survey")
    结束
    动画.输出(狐狸, 姿态)
    -- 然后像玩家一样：角色移动、重力、转向
结束

函数 狐狸模块.动画事件(狐狸, 实体号, 名字)
    如果 实体号 == 狐狸 和 名字 == "footstep" 那么
        世界.在位置播放声音("assets/sounds/footstep.wav", 实体.取位置(狐狸), 0.35)
    结束
结束
```

- 状态就是那串 `如果 / 否则如果`：从上往下，第一个成立的算数。加一个状态就是加一行。
- "刚才在跑吗"不用自己记，问 `动画.播放中`。这就是第 1 节说的"Lua 不保存状态"：状态在引擎里。
- 从走换到跑，脚本只是换了一个片段名；过渡是引擎自动做的。
- 脚步声不再用 12.3 那种"越过"计时，而是由片段里标好的时刻触发（`Fox.clips`），所以跑得快，脚步也快。

## 13. 动画

带骨骼的模型（glTF 里有 skin 的网格）由脚本每次更新给它一个**姿态**。引擎负责片段的时间、过渡和蒙皮；脚本只说"这一帧放哪个片段、怎么混合"。

### 13.1 每次更新：采样、混合、输出

```lua
令 姿态 = 动画.采样(e, "Walk")                -- 片段在它自己的时间上的姿态
动画.输出(e, 姿态)                            -- 这一帧 e 显示这个姿态
```

- `动画.采样(e, 片段 [, 速度, 循环])`：片段名就是 glTF 里动画的名字。第一次采样时从 0 开始，之后每次更新前进 `时间差 × 速度`；某次更新**没采样**它，它的时间就被丢掉，下次从头开始。`循环` 默认为真；假则停在最后一帧。
- `动画.输出(e, 姿态 [, 过渡秒数])`：每个角色每次更新输出一个姿态。没有输出的角色回到原始姿态（或者它的 `动画` 字段指定的片段，见 13.4）。
- 姿态只在得到它的那次更新里有效，不能存起来下一帧用。

**过渡是自动的。** 换了片段（这次采样了一个上次没采样的），引擎会从刚才显示的姿态平滑地过渡过去，大约 `过渡秒数`（默认 0.2）。所以写状态切换时不需要淡入淡出权重，直接换片段名就行。

### 13.2 混合与叠层

```lua
令 走 = 动画.采样(e, "Walk")
令 挥 = 动画.采样(e, "Wave")
令 姿态 = 动画.叠层(走, 挥, "b_Spine01_02", 1)   -- 脊椎以上挥手，腿继续走
动画.输出(e, 姿态)
```

- `动画.混合(甲, 乙, 权重)`：0 = 甲，1 = 乙，逐个关节插值。
- `动画.叠层(底, 上, 关节名, 权重)`：只在这个关节和它下面的关节上用 `上`。边界会在几个关节里渐变，不会在腰上硬切。
- 混合的两个姿态必须来自同一个实体。

### 13.3 问状态

| 写法 | 含义 |
|---|---|
| `动画.播放中(e, 片段)` | 上次或这次更新采样过它，并且（循环，或还没到结尾） |
| `动画.时间(e, 片段)` | → 当前秒数, 片段长度（没在播就是 0, 0） |
| `动画.跳转(e, 片段, 秒)` | 把正在播的片段移到某个时刻，不触发途经的事件，并从当前姿态过渡 |
| `动画.移动速度(e, 片段)` | 片段原本移动的速度（米/秒，已乘实体缩放） |
| `动画.关节(e, 关节名)` | → 关节的世界位置, 朝向（在 `动画.输出` 之后调用就是这一帧的） |

一次性的动作（攻击、开门）这样写：

```lua
如果 动画.播放中(e, "Attack") 或 输入.按下("J") 那么
    姿态 = 动画.采样(e, "Attack", 1, 假)   -- 播完一遍，播放中 就变成假，落到下面的条件
否则如果 ...
```

**原地播放。** 导入时引擎会把片段做成原地播放（去掉根骨骼一路走出去的位移），角色由脚本用 `实体.角色移动` 移动。去掉的速度记在 `动画.移动速度` 里：按 `速度 / 动画.移动速度(e, 片段)` 播放，脚就不会滑。本来就是原地制作的片段，移动速度为 0，就按 1 播放。

### 13.4 不写脚本：`动画` 字段

实体的 **动画** 字段（渲染分组）填一个片段名，运行时如果脚本没给它输出姿态，它就一直循环这个片段。适合只需要原地动的东西：站着的 NPC、风车、旗子。

关卡设置里的 **动画帧率** 让所有角色的姿态每秒只更新这么多次，像 PS1 那样一顿一顿的（0 = 每帧都更新）。片段的时间和事件不受影响。

### 13.5 片段文件与动画事件

3ds Max 一个场景只有一条时间轴，所以一个角色的所有动作依次排在时间轴上（待机 0–30 帧，走 40–64 帧……）。glTF 旁边同名的 `.clips` 文件告诉引擎怎么把它切成片段，以及片段里的事件：

```
# knight.clips
fps 30
[Idle 0 30]        # 片段 Idle = 时间轴第 0 到 30 帧
[Walk 40 64]
footstep 46        # 事件：同一条时间轴上的帧
footstep 57
```

- 数字都是帧（按 `fps`），就是在 Max 时间滑块上读到的数。时间轴请从第 0 帧开始。
- `[名字]` 不写范围，表示 glTF 里本来就叫这个名字的动画，整段作为片段；事件帧从它的开头算（`Fox.clips` 就是这样）。
- 循环的片段，最后一帧和第一帧摆成同一个姿势；片段之间留一帧空隙。
- 改了 `.clips` 会热重载。

不用手写：把 `tools/max/blimp_clips.ms` 放进 Max 的 `scripts\startup` 文件夹，重启 Max，菜单栏里就有 **Blimp > Blimp 动画片段**。片段和事件都是 Max 的**时间标签**，在时间滑块上看得见：

- 片段是 `▶Walk` 这样的标签，放在片段的第一帧，一直到下一个 ▶ 标签的前一帧。把滑块拖到下一个动作开始的地方，点「在滑块处切分」就行，不用对齐起止帧。
- 其他标签都是事件，落在哪个片段里就属于哪个片段。
- 每次在对话框里改动、每次保存 .max，都会重写 .max 旁边的 .clips（和导出的 glTF 放在一起）。

片段播过某个事件的那次更新之后，引擎调用 `世界.动画事件(实体号, 名字)`。只有在这个角色当前姿态里占一半以上的片段才触发，所以混合时脚步声不会响两遍；循环绕回开头时不会漏掉；跳转不触发。

## 14. 切换关卡

城堡里出生点左边有一个绿盒子，走进去就到了维多利亚办公室；办公室西走廊尽头也有一个，送你回城堡。这一节讲它是怎么做的。

### 14.1 玩家不跨关卡，状态跨关卡

切换关卡时，旧关卡的世界整个关掉，新关卡从它自己的文件载入，**没有哪个实体会活过切换**，玩家也不例外。每个有玩家的关卡都自己摆一个 `玩家`（和 `主相机`），走动的代码是同一个模块（12.6）。这样哪个关卡都能直接按运行来试，玩家也不是什么特殊对象。

要带到下一关的东西放进 **`游戏` 表**。它属于这次运行，而不属于某个关卡：

- 按运行时是空的，停止时清空；切换关卡时原样带到新关卡。
- 一个键存一个数字或一段文本，看最后一次用的是 `设数` 还是 `设文本`；没设过的键（或存的是另一种）读出 0 或 ""。最多 64 个键。
- 键可以用点分层：`玩家.生命值`、`玩家.入口`。存取和普通的键一样，只是查看的时候按层折叠（见下）。
- 热重载脚本不影响它（它在引擎里，不在 Lua 里）。

```lua
游戏.设数("血量", 实体.取数(玩家, "health"))   -- 离开前存（health 是自定义字段，见 4.4）
-- 下一关的 世界.开始 里：
实体.设数(玩家, "health", 游戏.取数("血量"))
```

运行时打开 **显示 → 游戏全局变量**，能看到 `游戏` 表里现在的每个值，分层的键折叠成组，数字和文本都能直接改。鼠标停在一行上显示完整的键。命令行也能查和改：

```
blimpctl globals 0                 # 全部（0 是关卡或它的运行副本的序号，见 blimpctl worlds）
blimpctl globals 0 金币            # 金币 组里的键：金币.总数、金币.城堡.1……
blimpctl globals 0 玩家.生命值 50   # 改一个键（原来是文本的还存成文本）
```

### 14.2 触发区

触发区是一个实体，把它的 **体积**（Volume）字段设成 **触发区**（Trigger）。它的盒子就是 **尺寸**（Size），以实体为中心，跟着实体旋转（缩放不算）。编辑器里画成绿色的框，图标点得到。

触发区自己什么都不做，由脚本每次更新问一次：

```lua
如果 实体.包含(门, 实体.取位置(玩家)) 那么
    -- 玩家的脚在盒子里
结束
```

`实体.包含(e, 点)`：点在不在 e 的盒子里。e 不是体积、或句柄无效时返回假。

测玩家时别直接用 `实体.取位置(玩家)`：它在脚底，而站在地上时脚底会压到地面下几毫米（角色移动每帧轻轻往下压，好保持着地），贴地摆的盒子就测不到，要跳起来才触发。玩家模块的 `出口` 测的是身体的中点（脚底往上半个身高）。

### 14.3 切换

```lua
游戏.设文本("入口", "从城堡来")
世界.切换关卡("assets/scenes/victorian_office.level")
```

`世界.切换关卡(路径)` 在**下一帧开始时**生效：这个关卡的运行世界关掉（脚本、声音、物理、动画都停），新关卡载入，接着运行，它的 `世界.开始` 在第一帧执行。

- 只有 `游戏` 表会带过去。新关卡要知道的事（从哪个入口出现）先写进去。
- 只换运行中的世界。编辑器里正在编辑的关卡不受影响，按停止回到它，不管中间切换了几次。
- 路径载入失败会记错误日志，游戏留在原来的关卡继续运行。

### 14.4 入口：玩家从哪里出现

入口就是新关卡里一个普通实体（城堡里的 `从办公室来`、办公室里的 `从城堡来`，没有模型，只有个图标），玩家放到它的位置、转到它的朝向。玩家模块把这几步包好了：

```lua
-- 世界.开始 里：游戏 表里有 "入口" 就站过去，然后把它清掉（热重载重跑 开始 时就不会再被拉回入口）
玩家模块.开始(玩家, 相机)

-- 世界.更新 里，每个出口一行：画出盒子，玩家走进去就存好入口、切换关卡
玩家模块.出口(玩家, 去办公室, "assets/scenes/victorian_office.level", "从城堡来")
```

入口别放在对面那个出口的盒子里，不然一到就又被送回去。直接按运行（不是从别的关卡过来）时 `游戏` 表里没有入口，玩家就在关卡里摆的位置。

### 14.5 金币：捡起来的东西跨关卡

城堡和办公室里各有 5 枚金币（名为 `金币_1` 到 `金币_5` 的实体，涂成金色的轮子），碰到就捡起，左上角显示一共捡了几枚。代码在 `assets/scripts/coins.luacn`，两个关卡共用：

```lua
令 金币模块 = 引入("assets/scripts/coins")

-- 世界.开始 里：这一关捡过的金币藏起来
金币模块.开始("城堡")

-- 世界.更新 里：转动、捡起
金币模块.更新("城堡", 玩家, 世界.时间())

-- 世界.界面 里：左上角画出个数（第 15 节）
金币模块.界面()
```

脚本不保存状态，所以要记的都在 `游戏` 表里：

- `"金币.总数"`：一共捡了几枚。
- `"金币.城堡.1"` 这样每枚一个键：这枚捡过没有（1 是捡过）。键里带上关卡名，两个关卡的 `金币_1` 才不会混在一起。都在 `金币` 组下，游戏全局变量窗口里折叠成 金币 → 城堡 / 办公室。

捡到的金币用 `实体.隐藏` 藏起来，不移除：移除后编号就断了，按编号找的循环会提前停下。回到一关时它从文件重新载入，金币全都在，`开始` 按 `游戏` 表把捡过的再藏好，所以它们不会因为切换关卡而重新出现。每个键占 `游戏` 表 64 个键里的一个，金币多了要换成别的记法（比如一关一个数字，每枚占一位）。

## 15. 屏幕界面

分数、血条、暂停菜单这类画在屏幕上的东西，在世界脚本的 `世界.界面` 回调里用 `界面` 表画（英文 `World.ui` 和 `UI`）：

```lua
函数 世界.界面()
    界面.位置(0.03, 0.04)
    界面.文字("金币  " .. 游戏.取数("金币.总数"), 矢量4(1, 0.85, 0.3, 1), 2)

    如果 世界.已暂停() 那么
        界面.窗口开始("暂停", 0.5, 0.5)   -- 画面正中的窗口
        如果 界面.按钮("继续") 那么
            世界.设暂停(假)
            输入.锁定鼠标(真)
        结束
        界面.窗口结束()
    结束
结束
```

### 15.1 回调

- `世界.界面` **每帧都调用，暂停时也调用**，这个世界在几个视口里显示就调用几次（游戏模式下就一次）。所以暂停菜单只能放在这里：暂停时 `世界.更新` 不执行。
- 这里只画界面、响应按钮。游戏逻辑还是放在 `世界.更新` 里。
- `界面.*` 只在这个回调里有效，在别处调用会在日志里报错，什么也不画。
- 界面是"立即模式"的：每帧把要显示的都画一遍，不画就没有。脚本不用记任何东西：控件的悬停、拖动由引擎记着；控件要改的值从 `游戏` 表或实体字段读进来，改完写回去（见下面的滑块）。
- 这一层用的是编辑器的界面库（Dear ImGui），字体和配色和编辑器一样，画在 PS1 后期效果之后，所以文字是清晰的，不会被抖动和降色。

### 15.2 位置和大小

位置和大小都**按视口宽高的比例**算，换窗口大小时界面还在同一个地方：`0, 0` 是左上角，`1, 1` 是右下角，`0.5, 0.5` 是正中。

- `界面.位置(x, y)`：下一个文字或控件的左上角放在哪里。用于直接画在画面上的界面；窗口里的控件自己从上往下排，不用它。
- `界面.同一行()`：下一个放在上一个的右边，而不是下面。
- `界面.分隔线()`、`界面.间距()`：一条横线、一点空白。

### 15.3 显示

- `界面.文字(文字 [, 颜色, 大小])`：一行文字。`大小` 是界面字号的倍数。不在窗口里时带阴影，画在什么背景上都看得清。
- `界面.进度条(比例 [, 宽, 高])`：填到 `比例`（0 到 1）的条，血量、计时。宽和高按视口的比例，省略时是视口宽度的四分之一、一行高。要标签就在旁边放一个文字：

```lua
界面.文字("血量")
界面.同一行()
界面.进度条(实体.取数(玩家, "health") / 100)
```

### 15.4 窗口

`界面.窗口开始(标题, x, y [, 宽, 高])` 和 `界面.窗口结束()` 之间的控件放进一个带背景和边框的面板。

- 窗口上比例为 `(x, y)` 的点放在视口里同样比例的地方：`0.5, 0.5` 居中，`1, 1` 贴右下角，`0, 0` 贴左上角。
- 宽和高按视口的比例；省略（或 0）时按内容自动大小。
- `标题` 画成窗口顶上的小标题，`""` 表示不要；它也用来区分两个窗口，所以同时显示的窗口标题别重复。
- 忘了 `窗口结束`，或者脚本在窗口中间出错，引擎会替你关上，不会搞坏界面。

### 15.5 控件

- `界面.按钮(标签)`：被点击的那一帧返回真。
- `界面.勾选框(标签, 值)`：显示 `值`，返回它，被点击的那一帧取反。
- `界面.滑块(标签, 值, 最小值, 最大值)`：显示 `值`，返回它，拖动时会变。

控件返回新值，脚本把它存回原来的地方：

```lua
游戏.设数("音量", 界面.滑块("音量", 游戏.取数("音量"), 0, 1))
```

- 点控件要用鼠标：打开菜单时 `输入.锁定鼠标(假)`，关菜单时再锁上。只显示文字和进度条不用放开鼠标。
- `标签` 显示出来，也用来区分控件，所以一个窗口里两个同名的控件要加隐藏后缀：`"确定##2"`（`##` 后面的不显示）。

### 15.6 暂停

- `世界.已暂停()`：游戏是否暂停（`世界.设暂停`，或编辑器里按 F6）。
- `世界.设暂停(布尔)`：暂停或继续。暂停时世界不再更新，时钟、物理、动画、声音都停住。继续只能在 `世界.界面` 里做，因为暂停时 `世界.更新` 不执行。

玩家模块（12.6）里：Esc 暂停并放开鼠标，`玩家模块.界面()` 在暂停时画出上面那个暂停菜单。
